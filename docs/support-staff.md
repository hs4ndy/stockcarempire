# Named support staff (VERSION114)

`js/data.js` owns STAFF_TYPES (role limits/series salary bases), STAFF_CANDIDATES (25 named candidates with OVR, salary multiplier and explicit effects), and shared effect helpers. `js/game.js` owns hiring, legacy normalization, payroll, repairs and sponsor payments. `js/race.js` consumes rated qualifying/simulation effects; `js/main.js` converts qualifying points to extra playable-grid draws. `js/ui.js` renders named roster/recruitment, OVR, costs, effects and a UI-only role filter.

Five candidates per role, 60/70/79/87/95 OVR. Byron Hill is a79 OVR Race Mechanic. Salaries are existing role/series bases times .55/.75/1/1.35/1.9; signing costs four salaries. Existing caps (1 chief,2 engineers,3 mechanics,2 analysts,2 directors) remain. Candidate identity cannot be hired twice; release permits rehire. Salary is fixed on hiring, paid each race.

Chiefs add1–3 simulated strategy score; engineers1–4 simulated setup score (best engineer applies, preserving legacy non-stacking). These do not assign actual finishing positions or change driven-race pace. Mechanics offer12–35% repair discounts; only best applies, no stacking. Analysts offer3–9 qualifying score and.5–2.5 simulated setup;87/95 OVR analysts each add TWO upgrade slots per tier, others one. Analyst effects add; simulated qualifying retains its14-point cap and driven qualifying retains its2-position setback. Directors add1–2 sponsor slots (still7 total cap) and2–10% sponsor income; income bonuses add and apply to regular payments/earned bonuses and skipped-race base payments. Budget forecasts include the base-income increase.

New contracts save candidateId, name, overall and explicit effects alongside existing IDs/types/salary. Old generic staff gain available named identities on load while keeping exact previous effects, salary, IDs and headcount. They gain no new director income bonus. Multiple legacy hires remain distinct. Previously installed upgrades are retained when an analyst leaves, but purchasing obeys the lower current cap. No migration resets career progress.

OVR describes recruitment quality; benefits are explicit data, not an inferred universal stat multiplier. Rebalance data and UI benefit descriptions together. Tests: test/support-staff.test.js and test/e2e/support-staff.spec.cjs. Source and standalone releases must stay synchronized.
